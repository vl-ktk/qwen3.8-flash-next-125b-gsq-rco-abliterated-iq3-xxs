## Пункт 14 — защищённые origin-запросы и аварийный отзыв (без выкладки на ПК)
- `src/cloudflare/origin-auth.mjs` и `src/windows/origin-auth.mjs`: одноразовая HMAC-SHA-256 подпись **каждого** запроса Worker → VPC origin, включая Ed25519 `/device/attest` и `/mcp` (GET/POST/DELETE). Подписаны метод, маршрут, точные байты body через SHA-256, фиксированные служебные заголовки (MCP session/method/name/version, device nonce/ID), timestamp и 128-битный nonce. Windows сравнивает HMAC constant-time, окно ±45 с, replay cache, лимит 2048 nonce. Неавторизованный локальный процесс на `127.0.0.1:8765` теперь получает 403. Без ключа default-deny. HTTP `/healthz` остаётся публичным локальным индикатором готовности, кроме режима emergency lock.
- `src/windows/main.mjs` при запуске требует `QWEN_MCP_GATEWAY_KEY_PATH` (файл с 32-байтовым секретом в base64url) и `QWEN_MCP_EMERGENCY_LOCK_PATH`. Облачный Worker требует **тот же** secret binding `QWEN_MCP_GATEWAY_KEY`. Ни один ключ в Git не сохранялся; текущий опубликованный Worker **не менялся**. Синхронная выдача и NTFS ACL — задача установщика (15–16), без неё новые source-сборки fail-closed.
- `src/windows/emergency-lock.mjs`, `admin-cli.mjs`: `lock`/`unlock` только в локальном интерактивном Windows-CLI с буквальным подтверждением. Наличие защищённого маркера блокирует MCP, attestation и health без рестарта; ошибка проверки состояния тоже блокирует. Аудит: существующий DO-аудит (7 дней); Windows выводит только фиксированные коды событий, без аргументов, токенов и данных инструментов. Логи и ACL обязан настроить установщик.
- `src/windows/security.test.mjs`, тест Cloudflare HMAC, end-to-end с реальным loopback; проверяется подделка, устаревшая подпись, replay, изменение body/path/method/headers, аварийная блокировка. **91/91** тест PASS, `npm run check`, Wrangler dry-run PASS. **PR #17 MERGED** (squash `df1cba2a91c7d11a1d2b20300eac8df01dd35bfc`), **GitHub CI #44692712409 SUCCESS**.
