# Требования к установщику

Цель: один `KTK-Windows-MCP-Setup.exe` (условное название) для Windows друга. **Пункт 16: source-only staging installer `Install-KTKMCP.ps1` добавлен, см. `docs/STEP_16_REPORT.md`. Это не готовый `Setup.exe`; облачный bootstrap, включение служб, подпись и испытания остаются пунктами 16–18.**

## Проверяемый пакет после пункта 15

Сборка `0.16.1` добавляет WinSW x64, XML двух Windows-служб, staging PowerShell-скрипт и отдельный `Activate-KTKMCP.ps1` для зашифрованного bootstrap через подтверждение владельца. Архив содержит manifest/SHA256SUMS и исключает ключи и токены. `ready_for_installation: false`: **его нельзя запускать на ПК друга** до полной приёмки.

### Режим staging

Для будущего испытания на отдельной тестовой Windows: проверка целостности `Verify-KTKPackage.ps1`, затем `Install-KTKMCP.ps1 -CheckOnly` (без изменения системы); только после проверки — повышенный UAC запуск установщика. Результат: `Program Files\KTK\QwenMCP`, `ProgramData\KTK\QwenMCP`, службы `KTKQwenMCP` и `KTKQwenTunnel` **не запущены**, marker `state\emergency.lock` присутствует. Это **не** полноценное подключение к ChatGPT, а только подготовка системы. Повторная установка отказывается изменять уже существующую систему.

### Защищённая активация — пока только исходник

Временный `Activate-KTKMCP.ps1` после staging связывается только с утверждённым `workers.dev`, генерирует ephemeral ключ в RAM, печатает код и fingerprint. Владелец открывает `/device/pair/manage` и подтверждает данные существующим паролем/CSRF. Worker возвращает зашифрованный **только для этого устройства** payload. Windows сохраняет секреты в `ProgramData` и включает службы только после локального self-test и подключения Tunnel. Без Cloudflare secrets или успешной проверки активация запрещена; аварийный lock остаётся. Этот механизм **пока не опробован на настоящей Windows и не включён в production Cloudflare**, а два скрипта не заменяют обещанный однопроходный Setup.exe.

## Подготовка заранее
1. Из проверенных исходников собрать конкретную версию Windows MCP.
2. Проверить источник и SHA/подпись `cloudflared`; включить или воспроизводимо устанавливать его.
3. Подготовить отдельный Cloudflare Tunnel и защищённый hostname; не встраивать постоянный Tunnel token в файл.
4. Реализовать одноразовую привязку с криптографической аутентификацией; ключ создаётся на устройстве при установке.
5. Сформировать подписанный/проверяемый пакет, манифест SHA256, документацию.
6. Протестировать на чистой тестовой Windows.

## Шаги для друга
1. Скачать пакет из проверенного источника и проверить его происхождение.
2. Запустить и подтвердить UAC.
3. Одобрить привязку ПК к личному MCP.
Иных ручных действий не планируется.

## Действия установщика
- Проверяет Windows, архитектуру, права, свободный диск и возможности автозапуска.
- Разворачивает MCP и `cloudflared`, изолированную конфигурацию и логи.
- Настраивает службу Windows / корректный режим запуска при входе, только нужные привилегии.
- Генерирует устройство-специфичные закрытые ключи, выполняет подтверждённую привязку.
- Проверяет local health, защищённое удалённое соединение и версию.
- При ошибке откатывает изменения и показывает диагностический код без секретов.
- Поддерживает обновление, rollback, ремонт и полное удаление с отзывом доступа.

## Отдельная загрузка AI
В установщик MCP **не входят** ~76 ГБ модели. После успешной установки и диагностики ПК веса SC117 скачиваются непосредственно на компьютер друга и проверяются хешами.

## Ограничения
- Windows UAC и согласие владельца обязательны.
- Автоматизация возможна только при реально работающих bootstrap/авторизации/сети; обещание «один клик» требует интеграционных испытаний.
- Установка системной службы не гарантирует управление интерфейсом активного пользователя; тестируется отдельно.
