## Найденная уязвимость и исправление

До пункта 14 локальный HTTP `127.0.0.1:8765/mcp` доверял localhost. OAuth, scope и Ed25519 проверялись на Cloudflare, но любой процесс на самом Windows-хосте мог обращаться к MCP-серверу напрямую. Даже read-only `file_read` с разрешёнными каталогами не должен был быть доступен такому клиенту.

Теперь Worker **после OAuth/scope** создаёт отдельную HMAC-SHA-256 подпись на каждый запрос к VPC origin. Подписываются `QWEN-ORIGIN-V1`, Unix-время в секундах, свежий 128-битный nonce, метод `GET|POST|DELETE`, фиксированный путь (`/mcp` либо `/device/attest`) и SHA-256 точных байтов тела. Windows проверяет подпись (constant-time), временное окно ±45 секунд и отсутствие повторного nonce в памяти запущенного сервера. Один nonce нельзя повторить даже с другим путём. Для больших потоков есть ограничение body 64 КиБ, одновременно хранится до 2048 свежих nonce; при исчерпании — отказ. Незаполненный/некорректный секрет закрывает доступ.

Секрет **не является Ed25519 приватным ключом устройства и не заменяет OAuth**. Ключ HMAC: случайные 32 байта, строка base64url без padding; в Cloudflare — будущий encrypted secret binding `QWEN_MCP_GATEWAY_KEY`, на Windows — содержимое ACL-защищённого файла из `QWEN_MCP_GATEWAY_KEY_PATH`. Сгенерировать и установить этот ключ **только в согласованном установщике**, ни в Git, ни в архив с исходником не включать. Развёртывание Worker и Windows runtime должно быть согласованным: при отсутствии ключа соединение **намеренно не работает**.

## Привилегии, подтверждение и аварийное отключение

- В удалённом MCP остаются только перечисленные read-only инструменты; нет произвольного PowerShell, write, службы и перезагрузки. `file_read` по умолчанию выключен, включается только при явно настроенных разрешённых путях и требуемом scope.
- `start`, `stop`, `restart`, `configure_recovery`, `reboot`, новые `lock`, `unlock` доступны **только через локальный интерактивный Windows CLI** с буквальной фразой подтверждения; перезагрузка также использует отдельный одноразовый код и отменяемый отсчёт из пункта 13. Нет удалённого маршрута для этих команд.
- Маркер по `QWEN_MCP_EMERGENCY_LOCK_PATH` моментально блокирует `/mcp`, `/device/attest`, `/healthz`. Если путь каталога недоступен или проверка состояния выдаёт ошибку — fail-closed. `unlock` требует нового локального подтверждения; CLI не принимает удалённых HTTP-команд.
- Cloudflare уже сохраняет краткий аудит с TTL 7 дней (маршрут, код, этап, стандартизированная причина, метод JSON-RPC); Windows отдаёт через stdout только фиксированные коды `origin_auth_denied`, `emergency_locked`, `tool_denied`, `tool_executed`, `tool_failed` + время. Нет секретов, headers, аргументов, имён файлов, содержимого файлов или stderr.

## Условия установки и ограничения

В пунктах 15–16 установщик должен: создать ACL-защищенный каталог и два Windows-файла (ключ и аварийный маркер — **маркер в норме отсутствует**, но его *родительский каталог* обязан существовать); назначить NTFS ACL для service identity/Administrators, убедиться в отсутствии доступа обычных пользователей; настроить отдельную Windows-службу с минимальными правами, без admin/System по умолчанию; настроить Worker secret без раскрытия; настроить защищённый журнал stdout и ротацию; проверить lock/unlock и смену/отзыв ключа. Пароль владельца/OAuth токены в пакет не класть. Если Worker secret и локальный ключ не совпадают, доступ закрывается до исправления конфигурации.

Проверка только на Linux: Node 24 + Miniflare + мок Windows API, в том числе реальный loopback HTTP и подпись Worker. **NTFS ACL, Windows Service/UAC, права на файл, Tunnel и полноценный ChatGPT → Windows путь не проверены.** Поэтому пункт 14 пока [ ] в roadmap.
