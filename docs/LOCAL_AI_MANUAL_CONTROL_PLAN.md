# План завершения локальной Qwen 125B и ручного управления RAM/VRAM

**Согласовано владельцем:** 21.11.2026. **Статус:** план, реализация и live-проверка не выполнены.
**Канонический исходник:** этот GitHub-репозиторий, ветка `main`.
**Область:** Windows KTK MCP + пользовательский Strata + модель SC117 IQ3_XXS на ПК друга. Никаких правок production/ПК/секретов самим этим планом.

## 1. Неподлежащие изменению требования владельца

1. Модель загружается в RAM/VRAM **только после явного нажатия кнопки «Загрузить модель»**.
2. Модель выгружается **только после явного нажатия кнопки «Выгрузить модель»**. Никаких таймеров простоя, скрытой авто-выгрузки или авто-загрузки после входящего запроса.
3. После ручной загрузки модель остаётся загруженной, пока владелец не нажмёт «Выгрузить», либо процесс не завершится из-за перезапуска/сбоя. После включения/перезапуска ПК состояние по умолчанию **«Выгружена»**, без восстановления загрузки.
4. Если модель выгружена, любой обычный запрос генерации получает понятное `model_not_loaded` и подсказку нажать кнопку. **Запрос не должен автоматически запускать Strata engine ни напрямую, ни через MCP, ни через прокси.**
5. Ручная выгрузка во время генерации: сразу перестать принимать новые задачи, дождаться **завершения текущих ответов**, затем безопасно освободить процесс модели. Не прерывать ответ и не использовать принудительное завершение для штатной выгрузки. На длительном ответе продолжать ожидать/отображать состояние; не объявлять успех по одному тайм-ауту.
6. Хранящиеся на SSD файлы весов не удаляются при выгрузке. Освобождается память **процесса**; системный файловый кэш Windows может оставаться в RAM — не обещать «0 байт».
7. Кнопки и статус доступны как минимум в локальной панели KTK на ПК с моделью. Любой удалённый контроль через MCP — отдельные явно авторизованные действия владельца, без автоматического вызова из обычных чатов/инференса.

## 2. Что уже есть, что подтверждено и чего пока нет

- **Подтверждённая запись о целевом ПК:** Intel Core i9-12900K, NVIDIA RTX 3090 Ti (24 GiB VRAM), 64 GiB RAM, NVMe C: и D: — `docs/LOCAL_MODEL_INSTALL_BLOCKS.md`. Это сохранённые характеристики, а **не новый live-замер** свободного места, драйвера или CUDA.
- **Модель:** `SC117/Qwen3.8-Flash-Next-GSQ-RCO-abliterated-GGUF`, точная квантизация `IQ3_XXS`, два shard-файла суммарно ~76.14 GB, отдельные файлы `strata/rt` (MTP) и native pack именно для SC117. Контроль ревизий и хешей уже описан в `src/windows/sc117-model.lock.json` и `docs/LOCAL_MODEL_INSTALL_BLOCKS.md`.
- **Движок:** в нашем источнике закреплены Strata `v0.2.17` и Control `0.1.63`. В официальной документации **именно тега v0.2.17** существуют `lazy_load`, `idle_unload_s`, `POST /v1/load`, `POST /v1/unload` и `?wait=1`.
- **Критическое несоответствие требованиям:** `lazy_load: true` **сам по себе недопустим**: upstream Strata автоматически загружает движок на первом запросе генерации. Для ручного режима обязателен отдельный контроль входящих запросов и прямого доступа к Strata.
- **Реализованные исходники:** read-only preflight, pin/verify Strata, resume+verify+pack SC117, интегрированный Setup и одноразовая inference-acceptance с остановкой движка. `src/windows/local-ai-setup.mjs` по окончании установки вызывает тест инференса; `src/windows/sc117-inference.mjs` запускает/останавливает тестовый процесс. **Постоянного владельческого контроллера с кнопками и жёсткой ручной блокировкой пока нет.**
- **MCP-only автообновление** `0.18.12 → 0.18.16` на слабом ПК владельца реально прошло, записано в `HANDOFF.md`. Это **не** является проверкой Qwen 125B/Strata на другом ПК.
- **Не проверены вживую на целевом ПК:** свободное место, установленный драйвер/CUDA, Strata engine, скачивание ~77 GB, native pack, запуск модели, скорость и расход RAM/VRAM. **Запуск не объявлять готовым.**

## 3. Очередь оставшихся работ

### A. Безопасная подготовка и реальный preflight ПК друга

- [ ] Перед изменениями зафиксировать текущие commit SHA, опубликованную версию MCP/установщика, релиз и идентификатор отката; не смешивать исходник и production.
- [ ] На **ПК друга**, read-only: Windows x64, i9-12900K, 64 GiB RAM/свободная RAM, `nvidia-smi` и NVIDIA driver/CUDA-совместимость, RTX 3090 Ti и действительная VRAM; статус имеющихся Strata/Python/служб.
- [ ] Измерить свободное место именно на целевом томе C:/D:, тип носителя и путь установки; цель **~130 GB свободно на одном томе** (консервативная рекомендация, не формальный upstream минимум).
- [ ] Если CUDA, RAM, диск или целостность данных не подходят, прервать до многогигабайтной загрузки с понятной причиной; не снижать квантизацию и не переходить на облачную модель без решения владельца.

### B. Контроллер модели: строго ручные load/unload

- [ ] Добавить отдельный пользовательский Windows-компонент управления KTK Strata (не SYSTEM), с единоличным владельцем процесса/профиля, фиксированными путями и строгой авторизацией.
- [ ] Состояния: `not_installed`, `unloaded`, `loading`, `loaded`, `busy`, `draining`, `unloading`, `error`; разнести **факт по API движка** и отображаемое намерение.
- [ ] Реализовать кнопку **«Загрузить модель»**: только этот action запускает или подгружает движок, проверяет owner/instance, auth, health, при необходимости первую генерацию; при ошибке безопасно возвращает `unloaded/error`.
- [ ] Реализовать кнопку **«Выгрузить модель»**: атомарно закрыть очередь новых запросов, дождаться активных генераций, обратиться к защищённому Strata `/v1/unload?wait=1` или эквивалентному guarded stop; подтвердить `unloaded` по API и состоянию процесса; не убивать чужие процессы. Если активность дольше лимита upstream (обычно 300 s), повторять ожидание без принудительного убийства.
- [ ] Отключить автоматическую выгрузку (`idle_unload_s: 0`/отсутствует) и любые фоновые попытки загружать модель.
- [ ] Убрать **обход ручного режима**: KTK proxy/MCP не отправляет запросы генерации в Strata, пока владелец не нажал «Загрузить». Прямой loopback endpoint Strata должен быть защищён и не использоваться в качестве публичного inference endpoint, способного проснуть модель. Одной опции `lazy_load` недостаточно; выбрать и протестировать реальное enforcement (процесс Strata выключен до нажатия либо gateway с проверяемой защитой всех входов).
- [ ] После сбоя/reboot/обновления синхронизировать состояние по фактам и оставаться **без автозагрузки**; две кнопки и параллельные запросы не должны запускать две копии модели; блокировки и ошибки должны быть восстановимы.

### C. Кнопки, установщик и обновления

- [ ] Добавить локальную панель KTK: **«Загрузить модель»**, **«Выгрузить модель»**, текущий статус, активные запросы, RAM/VRAM (если доступны), прогресс и понятные ошибки.
- [ ] Уточнить/реализовать доступ к этой панели со стороны пользователя ПК друга; удалённое управление через ChatGPT — только если отдельно разрешено и через минимальные scoped MCP actions, никогда произвольная команда или shell.
- [ ] Изменить **установщик**, чтобы скачивание и подготовка файлов не вызывали скрытый запуск engine. Первый live тест — после явного действия владельца «Загрузить/Проверить»; обычная установка заканчивается **выгруженной** моделью.
- [ ] Изменить повторную user-phase проверку при **MCP-обновлении**: автообновление MCP не должно запускать inference/test или автоматически менять состояние RAM/VRAM. Не трогать работающий ответ/чужой процесс.
- [ ] Сохранить resumable download с SHA-256 проверками и отдельный SC117 native pack/MTP; корректно продолжать после обрыва/повторного запуска, не удалять проверенные модели и чужие установки.

### D. Проверка до выкладки

- [ ] Unit+integration: переходы состояний, повторные клики, параллельная загрузка, старый статус, некорректный PID, ошибочный owner, отказ GPU, 409/busy, timeout, отказ Strata, падение процесса.
- [ ] Негативные тесты **no-auto-load**: запрос при `unloaded`, входящий после выгрузки, >10 минут простоя, перезапуск службы/ПК, MCP auto-update, прямой доступ к Strata. Ни одно событие не начинает загрузку без кнопки.
- [ ] Сценарий «длинный ответ + кнопка выгрузки»: ответ не прерывается, новые запросы не принимаются, после ответа engine выгружается; проверить отсутствие фонового автозапуска.
- [ ] Windows CI: PowerShell 5.1, пользовательский процесс, ACL/loopback/auth, упаковка Setup.exe, тестовое окно и симуляция отказов; `npm test`, `npm run check`, `npm run check:local-ai`.
- [ ] Документировать модель угроз (MCP не arbitrary shell), ограничения системного file cache и процедуру ручного recovery.

### E. Реальная установка/приёмка на ПК друга (отдельное согласие)

- [ ] Перед запуском сверить последнюю версию источника, выпустить отдельный проверенный тестовый установщик с новой версией, опубликовать точные SHA-256 и сохранить предыдущий пакет для отката.
- [ ] Локально с разрешения владельца пройти Windows UAC, привязку MCP, установку Strata/CUDA, SHA-проверенную загрузку обоих shards + MTP, native pack; после установки проверить `unloaded` и отсутствие занятой VRAM движком.
- [ ] Нажать **«Загрузить модель»**; записать время старта, RAM/VRAM, ответы на коротком и длинном контексте, реальную скорость, нагрузку и отсутствие ошибок.
- [ ] Нажать **«Выгрузить модель»** во время активного ответа; убедиться в graceful drain и фактическом завершении engine. Запрос после выгрузки должен быть отклонён без загрузки.
- [ ] Проверить повторную ручную загрузку, простой >10 мин, перезагрузку, обновление MCP и повторную установку; подтвердить отсутствие автоматического старта/остановки весов.
- [ ] По итогу зафиксировать результаты, версии, контрольные суммы, команду/пакет отката и реальные ограничения. До этих проверок статус **не production-ready**.

## 4. Критерии «готово»

- [ ] Файлы SC117 IQ3_XXS установлены и проверены на ПК друга; Strata/CUDA действительно генерирует ответы.
- [ ] Загрузка и выгрузка работают **только по кнопкам**, в том числе после перезагрузки/обновления, без таймеров и автоматического пробуждения от запроса.
- [ ] Кнопка выгрузки ждёт окончания ответа, не теряя данные и не убивая чужую сессию.
- [ ] Подтверждены по измерениям RAM/VRAM до, во время и после загрузки; значение Windows file cache не выдаётся за занятую память модели.
- [ ] Установщик и updater не обходят ручное правило, ошибки обрабатываются безопасно, есть проверенный откат и HANDOFF.
