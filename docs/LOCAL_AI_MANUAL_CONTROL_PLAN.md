## 1. Неподлежащие изменению требования владельца

1. **Единственное исключение при первичной установке:** после явного выбора владельцем установки локальной AI установщик один раз загружает Qwen в RAM/VRAM, проверяет реальный ответ через CUDA/Strata и **обязательно останавливает именно запущенный им процесс**. При неудачной остановке — `failed/manual_attention`, не «успешно установлено». Проверенные файлы остаются на SSD. Это разрешённый installation acceptance, а не штатное использование. **Не удалять этот тест из существующего `local-ai-setup.mjs`/`sc117-inference.mjs`.** Remote MCP-подготовка из этапа 3 по-прежнему скачивает только файлы и не запускает inference.
2. **После завершения установочного теста** обычная загрузка модели в RAM/VRAM — исключительно по явной кнопке «Загрузить модель»; обычная выгрузка — исключительно по кнопке «Выгрузить модель». Никаких таймеров простоя, скрытой авто-выгрузки или авто-загрузки после входящего запроса.
3. После ручной загрузки модель остаётся загруженной, пока владелец не нажмёт «Выгрузить», либо процесс не завершится из-за перезапуска/сбоя. После включения/перезапуска ПК состояние по умолчанию **«Выгружена»**, без восстановления загрузки.
4. Если модель выгружена, любой обычный запрос генерации получает понятное `model_not_loaded` и подсказку нажать кнопку. **Запрос не должен автоматически запускать Strata engine ни напрямую, ни через MCP, ни через прокси.**
5. Ручная выгрузка во время генерации: сразу перестать принимать новые задачи, дождаться **завершения текущих ответов**, затем безопасно освободить процесс модели. Не прерывать ответ и не использовать принудительное завершение для штатной выгрузки. На длительном ответе продолжать ожидать/отображать состояние; не объявлять успех по одному тайм-ауту.
6. Хранящиеся на SSD файлы весов не удаляются при выгрузке. Освобождается память **процесса**; системный файловый кэш Windows может оставаться в RAM — не обещать «0 байт».
7. **Панель делаем ПОСЛЕ первичной установки и приёмки модели.** Единая адаптивная `KTK Local AI` для Windows 11, iPhone, iPad и Android: чат с Qwen, история и поток ответов, отдельные кнопки «Загрузить»/«Выгрузить», статус, RAM/VRAM, GPU, скорость, установка/ремонт и настройки. Не запускать разработку кнопок до первого установочного acceptance.
8. **Удалённая панель с телефона или планшета** работает через защищённый Cloudflare Tunnel + Access (отдельный hostname, допуск только владельца через Google и проверка токена у origin). Никакого открытого наружу порта Strata/MCP или прямого публичного API управления моделью. При выключенном/недоступном ПК или отсутствии интерактивной пользовательской сессии — честное «недоступно»; удалённая кнопка не должна автоматически входить в Windows, отключать UAC или запускать модель без нажатия.

### Этап 2. Безопасные **инструменты настройки и восстановления ПК через MCP**

**Новое обязательное решение владельца от 21.11.2026:** на Windows 11 ПК друга **не должно быть подтверждений или ручных команд** при удалённой настройке. В процессе первоначального установки `KTKQwenUpdater` один раз получает права LocalSystem с возможным штатным UAC; дальше привилегированная служба выполняет **только ограниченные KTK-действия** по отдельному OAuth `qwen:maintenance`, HMAC на `127.0.0.1`, одноразовому плану на 5 минут и явно подтверждённому владельцем действию в **чате**. MCP LocalService не получает неограниченного администрирования Windows, сторонние службы/процессы/драйверы/защита ОС недоступны. Правило **только по кнопке** для загрузки/выгрузки модели не изменяется.

**Реализовано в исходниках:** три MCP-команды `pc_maintenance_preview`, `pc_maintenance_apply`, `pc_maintenance_status`; десять фиксированных действий с собственным обратным действием: (1) `start_ktk_tunnel`/`rollback_ktk_tunnel`, (2) `enable_ktk_tunnel_autostart`/`rollback_ktk_tunnel_autostart`, (3) `enable_ktk_mcp_autostart`/`rollback_ktk_mcp_autostart`, (4) `enable_ktk_updater_autostart`/`rollback_ktk_updater_autostart`, (5) `quarantine_ktk_staging`/`restore_ktk_staging`. Для каждой службы сверяется точный бинарник WinSW в защищённом KTK-каталоге, статус и тип старта. Нельзя остановить MCP/Updater/модель, изменить чужую службу или запускать произвольный скрипт. Защищённый `pending`-журнал позволяет откатить даже частично применённую операцию. Действия подтверждаются владельцем **в чате**, никаких UAC и консоли на ПК после первичного bootstrap. Откат туннеля может оборвать канал; это предупреждается в preview. Read-only `pc_performance_advice` сообщает RAM/VRAM и Windows 11 рекомендации без OS-правок.

**Важно про staging:** новый updater 0.18.19 помечает каждую свою `update-XXXXXX` папку криптографическим HMAC; после аварии только старую (≥24 часов), проверенную KTK-папку с разрешёнными файлами можно переместить в карантин, а затем восстановить одним owner-approved действием. Папки предыдущих updater без подписи, симлинки/reparse, неизвестные файлы, пользовательские `.part` (в том числе будущие 77-ГБ shards), общий Windows Temp и Downloads **не затрагиваются**. Перемещение происходит на том же диске: **освобождено 0 байт**. Безопасного удалённого массового удаления файлов нет — для необратимого удаления нет rollback, поэтому его намеренно не разрешали.
