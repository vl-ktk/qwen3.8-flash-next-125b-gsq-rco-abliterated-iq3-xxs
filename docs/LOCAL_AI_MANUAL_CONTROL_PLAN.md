# План завершения локальной Qwen 125B и ручного управления RAM/VRAM

**Согласовано владельцем:** 21.11.2026. **Статус:** единый обновлённый план, этапы до установки на ПК друга; реализация новых инструментов и live-проверка не выполнены.
**Канонический исходник:** этот GitHub-репозиторий, ветка `main`.
**Область:** Windows KTK MCP + пользовательский Strata + модель SC117 IQ3_XXS на ПК друга под **Windows 11** (уточнение владельца 21.11.2026). Никаких правок production/ПК/секретов самим этим планом.

## 1. Неподлежащие изменению требования владельца

1. Модель загружается в RAM/VRAM **только после явного нажатия кнопки «Загрузить модель»**.
2. Модель выгружается **только после явного нажатия кнопки «Выгрузить модель»**. Никаких таймеров простоя, скрытой авто-выгрузки или авто-загрузки после входящего запроса.
3. После ручной загрузки модель остаётся загруженной, пока владелец не нажмёт «Выгрузить», либо процесс не завершится из-за перезапуска/сбоя. После включения/перезапуска ПК состояние по умолчанию **«Выгружена»**, без восстановления загрузки.
4. Если модель выгружена, любой обычный запрос генерации получает понятное `model_not_loaded` и подсказку нажать кнопку. **Запрос не должен автоматически запускать Strata engine ни напрямую, ни через MCP, ни через прокси.**
5. Ручная выгрузка во время генерации: сразу перестать принимать новые задачи, дождаться **завершения текущих ответов**, затем безопасно освободить процесс модели. Не прерывать ответ и не использовать принудительное завершение для штатной выгрузки. На длительном ответе продолжать ожидать/отображать состояние; не объявлять успех по одному тайм-ауту.
6. Хранящиеся на SSD файлы весов не удаляются при выгрузке. Освобождается память **процесса**; системный файловый кэш Windows может оставаться в RAM — не обещать «0 байт».
7. Кнопки и статус доступны как минимум в локальной панели KTK на ПК с моделью. Любой удалённый контроль через MCP — отдельные явно авторизованные действия владельца, без автоматического вызова из обычных чатов/инференса.

## 2. Что уже есть, что подтверждено и чего пока нет

- **Подтверждённая запись о целевом ПК:** Intel Core i9-12900K, NVIDIA RTX 3090 Ti (24 GiB VRAM), 64 GiB RAM, NVMe C: и D: — `docs/LOCAL_MODEL_INSTALL_BLOCKS.md`. Это сохранённые характеристики, а **не новый live-замер** свободного места, драйвера или CUDA.
- **Модель:** `SC117/Qwen3.8-Flash-Next-GSQ-RCO-abliterated-GGUF`, точная квантизация `IQ3_XXS`, два shard-файла суммарно ~76.14 GB, отдельные файлы `strata/rt` (MTP) и native pack именно для SC117. Контроль ревизий и хешей уже описан в `src/windows/sc117-model.lock.json` и `docs/LOCAL_MODEL_INSTALL_BLOCKS.md`.
- **Движок:** в нашем источнике закреплены Strata `v0.2.17` и Control `0.1.63`. В официальной документации **именно тега v0.2.17** существуют `lazy_load`, `idle_unload_s`, `POST /v1/load`, `POST /v1/unload` и `?wait=1`.
- **Критическое несоответствие требованиям:** `lazy_load: true` **сам по себе недопустим**: upstream Strata автоматически загружает движок на первом запросе генерации. Для ручного режима обязателен отдельный контроль входящих запросов и прямого доступа к Strata.
- **Реализованные исходники:** read-only preflight, pin/verify Strata, resume+verify+pack SC117, интегрированный Setup и одноразовая inference-acceptance с остановкой движка. `src/windows/local-ai-setup.mjs` по окончании установки вызывает тест инференса; `src/windows/sc117-inference.mjs` запускает/останавливает тестовый процесс. **Постоянного владельческого контроллера с кнопками и жёсткой ручной блокировкой пока нет.**
- **MCP-only автообновление** `0.18.12 → 0.18.16` на слабом ПК владельца реально прошло, записано в `HANDOFF.md`. Это **не** является проверкой Qwen 125B/Strata на другом ПК.
- **Не проверены вживую на целевом ПК:** свободное место, установленный драйвер/CUDA, Strata engine, скачивание ~77 GB, native pack, запуск модели, скорость и расход RAM/VRAM. **Запуск не объявлять готовым.**

## 3. Очередь работ: **СНАЧАЛА MCP-инструменты для настройки ПК, ПОТОМ установка на ПК друга**

В самом начале этапа 7 допускается только чтение диагностических фактов реального ПК через подготовленный MCP. Ни скачивание ~77 GB, ни CUDA inference, ни изменение Windows до проверки и отдельного разрешения владельца. Тесты CI не заменяют последующую живую приёмку.

### Этап 1. Расширить **диагностику ПК через MCP** (до модели, только чтение)

**Текущий кандидат:** код шести read-only инструментов подготовлен для тестового пакета `0.18.17`, проверены офлайн-тесты; до подтверждения **нативного Windows CI и публикации** этап не помечен завершённым. При отсутствии CUDA execution, пользовательского Strata или достоверного соответствия C:/D: инструмент показывает `unknown`/`needs_action`, а не обещает готовность.

**Что уже есть в подключённом MCP — 13 инструментов, новых не заявлять как готовые:**

- Read-only: `system_info`, `system_monitor`, `process_list`, `service_status`, `app_status`, `admin_status`, `pc_preflight`, `storage_check`, `runtime_check`, `installation_plan`, `update_status`.
- Запись **только в KTK-update scope**: `update_apply`, `update_resume`. Они не дают свободной настройки Windows. Исходники: `src/windows/windows-tools.mjs`, `monitoring.mjs`, `model-preflight.mjs`.

**Разработать недостающие инструменты (имена предварительные, API ещё нет):**

- [ ] `pc_full_audit`: версия Windows и совместимость, x64/права текущего пользователя/служб, CPU/инструкции при возможности надёжной проверки, RAM total/available/commit pressure, файл подкачки (размер и режим), pending reboot и признаки системных проблем без раскрытия личных данных.
- [ ] `pc_gpu_audit`: точная модель RTX, VRAM total/free/used, NVIDIA driver, CUDA driver/runtime/подходящий engine, занятость GPU другими процессами, телеметрия температур при поддержке; **выполнение CUDA кода** — отдельный контролируемый тест, не выводить «совместимо» по одному наличию `nvidia-smi`.
- [ ] `pc_storage_audit`: реальные C:/D: — ёмкость, свободные байты, тип ФС и доступность записи для KTK, сопоставление буквы тома с физическим NVMe (если подтверждаемо); оценка файлов модели, пакета, временных данных и резервного места. 130 GB — рекомендация, минимум вычислять по фактической задаче. Отдельно проверить здоровье диска лишь если данные доступны.
- [ ] `pc_memory_audit`: процессы, потребляющие RAM, GPU VRAM, давление памяти, объём памяти самого Strata и доступный запас. Не выгружать ОС/чужие приложения ради красивой цифры «свободно».
- [ ] `pc_install_diagnostics`: признаки уже установленного Strata/CUDA/пакетов, выбранный KTK каталог, отсутствие конфликтующих инстансов, установочные журналы KTK, ошибки Windows service/task, доступная сеть для pinned download, рекомендации/блокеры.
- [ ] `pc_readiness_report`: единый результат `ready / needs_action / blocked / unknown` с **точной причиной**, проверенными фактами, неопределённостями и планом исправлений; никаких изменений от вызова. При неизвестных GPU/дисках не давать ложный PASS.

**Готово по этапу:** на offline fixtures и Windows CI каждое поле/ошибка/ограничение проверены; MCP отдаёт понятный отчёт без доступа к произвольному файловому содержимому и секретам.

### Этап 2. Безопасные **инструменты настройки и восстановления ПК через MCP**

- [ ] Реализовать `pc_maintenance_preview`: показать, **что именно** будет изменено, зачем, риск, нужны ли UAC/перезагрузка, сколько места реально будет освобождено (оценка), как отменить и вернуть обратно. Чтение не означает разрешение на применение.
- [ ] Реализовать `pc_maintenance_apply`: только жёсткий список заранее реализованных операций с отдельным явным подтверждением владельца, проверкой текущего состояния, ограниченными путями/сервисами, журналом и откатом. **Не произвольный PowerShell и не общий администратор Windows.**
- [ ] Разрешённые для проектирования операции: безопасная проверка/восстановление **только KTK-служб и задач** (сохранить прежнюю конфигурацию), восстановление завершённой/прерванной установки KTK/Strata, очистка **только подтверждённых KTK-owned** временных `.part`/staging после preview, диагностика места и кэшей. Любые пользовательские Downloads, Temp всего Windows, корзина, драйверы и сторонние процессы — вне автоматического удаления; системную очистку можно предложить открыть в штатных настройках Windows.
- [ ] Настройки производительности (план питания, автозагрузка, страница подкачки, фоновые программы, системные обновления) — сначала read-only рекомендации. Если реализуется reversible изменение конкретной настройки: отдельный preview, разрешение, снимок старого значения и проверенный rollback; не отключать Defender, обновления, UAC, не править реестр вслепую.
- [ ] Для **RAM**: вместо фиктивной «очистки оперативки» показывать давление памяти, источники потребления и освобождать только **свою модель** по кнопке владельца. Не принуждать Windows сбрасывать file cache/standby list, не убивать игры и процессы пользователя.
- [ ] Для **GPU**: показать, кто занимает VRAM, CUDA/driver warnings, помочь закрыть конфликтующий софт вручную; не делать GPU reset/driver update без отдельного согласия, проверки и страховки.
- [ ] Команды диагностики/установки не должны получать значения shell, произвольные URL, пути, названия чужих процессов или секреты от ChatGPT. Ограничить KTK-owned ресурсы, учётную запись, scopes, ACL, audit и timeouts.

**Готово по этапу:** безопасный preview→apply→verify→rollback для каждого разрешённого действия, отказ на неподдерживаемых путях и операциях; негативные тесты на попытки изменить чужие данные.

### Этап 4. **Ручная** загрузка и выгрузка модели — без исключений

- [ ] Отдельный KTK-owned user controller, состояния `not_installed`, `unloaded`, `loading`, `loaded`, `busy`, `draining`, `unloading`, `error`; после boot/restart без автоматической загрузки.
- [ ] Две реальные кнопки в локальной панели: **«Загрузить модель»** и **«Выгрузить модель»**; статус и доступная RAM/VRAM. Обычный MCP-запрос не может нажать их сам, а при `unloaded` получает отказ `model_not_loaded`.
- [ ] **«Загрузить»**: единственный owner-approved переход к размещению weights в RAM/VRAM, проверка версии/владения/состояния; повторный клик не запускает вторую копию.
- [ ] **«Выгрузить»**: прекратить приём новых inference-запросов, дождаться текущего ответа, затем корректно выгрузить только свой engine. Подтвердить освобождение process RAM/VRAM, не обещать очистить OS file cache. Без force-kill при штатной операции.
- [ ] Strata `v0.2.17` поддерживает ручные `/v1/load` и `/v1/unload`, но `lazy_load: true` **может автоматически загрузить модель на запросе**. Поэтому одного native Strata config мало: необходим жёсткий gateway/process gate, который невозможно обойти прямым inference endpoint. `idle_unload_s: 0`/отсутствует; без таймера.
- [ ] Отдельные негативные тесты: прямой запрос после выгрузки, запрос после reboot, >10 минут простоя, auto-update, installer, ручная выгрузка при долгом ответе. Все сценарии «без кнопки» остаются unloaded. Не добавлять авто `Games Mode`, который сам выгружает Strata.

**Готово по этапу:** все загрузки и выгрузки происходят **только по нажатиям**, не по таймеру, запуску программы, запросу, автообновлению или установке.
